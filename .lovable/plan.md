# إدارة المستخدمين والصلاحيات

## نظرة عامة

إضافة نظام كامل لإدارة المستخدمين يتضمّن:
- موافقة الأدمن على التسجيلات الجديدة قبل تفعيل الحساب
- تعيين الأدوار (admin / account_manager / marketer)
- ربط مجموعة مسوّقين بمدير حساب محدد
- صفحة إدارة شاملة للأدمن

## التغييرات في قاعدة البيانات

### 1. إضافة حالة الموافقة على المستخدمين
حقل `status` في جدول `profiles`:
- `pending` — بانتظار موافقة الأدمن (الافتراضي عند التسجيل)
- `approved` — مفعّل
- `rejected` — مرفوض

### 2. تعديل دالة `handle_new_user`
لتعيين `status = 'pending'` تلقائياً عند التسجيل (بدون role).

### 3. تعديل سياسات RLS
- المستخدم `pending` لا يستطيع قراءة أي بيانات حساسة (marketers, orders, ad_spend...) — فقط profile الخاص به.
- الأدمن يستطيع رؤية وتعديل كل profiles وuser_roles.

### 4. ربط المسوّقين بمدير حساب
- `marketers.account_manager_id` موجود بالفعل
- إضافة سياسة: account_manager يرى فقط المسوّقين المرتبطين به (بدلاً من رؤية الكل)
- إضافة سياسات مماثلة على `orders`, `ad_spend_transactions`, `ad_accounts` للفلترة حسب المسوّقين التابعين

## التغييرات في الواجهة

### 1. صفحة `/users` (للأدمن فقط)
- جدول المستخدمين مع: الاسم، البريد، الحالة، الأدوار، تاريخ التسجيل
- أزرار: موافقة / رفض / تعيين دور / تغيير دور / حذف
- في حالة `account_manager`: اختيار قائمة المسوّقين المرتبطين به

### 2. تعديل `/login`
- إذا كان المستخدم `pending`: عرض رسالة "حسابك بانتظار موافقة الأدمن" وتسجيل خروج تلقائي
- إذا كان `rejected`: رسالة "تم رفض طلب التسجيل"

### 3. تعديل `AppSidebar`
- إضافة رابط "إدارة المستخدمين" يظهر للأدمن فقط

### 4. تعديل `auth-context`
- تحميل `status` ضمن بيانات المستخدم
- منع الوصول لأي صفحة محمية إذا كان الحساب غير معتمد

### 5. صفحة تفاصيل مدير الحساب
- في صفحة `/users/$id` للمستخدم من نوع `account_manager`: قسم لإسناد/إزالة مسوّقين

## ملفات جديدة
- `src/routes/_authenticated/users.index.tsx` — قائمة المستخدمين
- `src/routes/_authenticated/users.$id.tsx` — تفاصيل المستخدم + إسناد مسوّقين
- migration جديدة لتغييرات قاعدة البيانات

## ملفات معدّلة
- `src/lib/auth-context.tsx` — إضافة status
- `src/routes/login.tsx` — رسائل الحالة
- `src/routes/_authenticated.tsx` — منع غير المعتمدين
- `src/components/AppSidebar.tsx` — رابط إدارة المستخدمين
- `supabase/migrations/...` — schema + RLS

## ملاحظات تقنية
- استخدام `supabaseAdmin` عبر `createServerFn` لعمليات الأدمن الحساسة (تعيين أدوار، حذف مستخدمين، تغيير حالة)
- المسوّق الموجود حالياً (جدول `marketers`) يبقى ككيان منفصل عن المستخدم. ربط المسوّق بحساب مستخدم يتم عبر `marketers.user_id` (موجود بالفعل).
